# Zad Al-Muslim (Tasbee7): working conventions

## Git
- Commit messages follow Conventional Commits: `type(scope): description`.
  - Types: `feat`, `fix`, `refactor`, `perf`, `style`, `docs`, `test`, `chore`, `ci`, `build`.
  - Scope: the page or module, e.g. `video-maker`, `audio`, `quran`, `sw`, `i18n`.
  - Description: imperative and lower-case; add a body that explains what changed and why
    when it isn't obvious.
- Branch names describe the change: `feat/<topic>`, `fix/<topic>`, `docs/<topic>`, …
- No attribution or session lines in commits (no Co-Authored-By, no session links), and no
  "Generated by" footer in PR bodies or comments.
- One clean PR per piece of work, from a fresh branch off the latest `main`.

## Product
- Keep the app's backgrounds and its light / dark / sepia themes.
- Don't reduce image or video quality.
- When cached files change, bump `CACHE_NAME` in `sw.js` with a one-line note.
