# Video-maker backgrounds — process new media (OpenCode prompt)

Run from the repo root after dropping new images/videos into `images/video-maker/`:

```bash
~/tools/opencode-delegate "G:/Github Repos/Tasbee7" "$(cat images/video-maker/update.md)" 900
```

Everything below this line is the prompt.

---

Stack: static PWA (no build step). Background media for `pages/video-maker.html` lives in
`images/video-maker/`; the page reads `images/video-maker/manifest.json` (a flat JSON array of
filenames) which is generated by `scripts/gen-video-bgs.cjs` (`npm run bgs:video`).
Tools available: `ffmpeg` / `ffprobe` (8.x, libx264 + libwebp), Python 3 with Pillow (WebP support).
Shell is Git Bash on Windows — the repo path contains a space, always quote paths.

TASK: Find media in `images/video-maker/` that has not been optimised yet, convert it to the
formats below, keep every original, and regenerate the manifest. Do the work now; do not just
describe it.

## 0. Rules (must hold for every step)
- NEVER delete or overwrite an original. Before converting or replacing any file, move the source
  into `images/video-maker-originals/`. If a file with the same name already exists there, add a
  suffix (`name-2.ext`, `name-3.ext`, ...) instead of overwriting.
- Do not edit any code (`*.js`, `*.html`, `*.cjs`, `sw.js`) and do not edit this `update.md`.
- Ignore in `images/video-maker/`: `manifest.json`, `update.md`, any `*.thumb.webp`.
- The process must be idempotent: running it twice in a row changes nothing the second time.
- Do not commit.

## 1. Inventory — decide what needs work
List every file in `images/video-maker/` (except the ignored ones above) and classify it:

| Kind | Extensions | Needs processing when |
|---|---|---|
| Image | png, jpg, jpeg, avif, bmp, tif, tiff, gif (first frame), heic if Pillow can open it | extension is not `.webp`, OR it is `.webp` but larger than 600 KB, OR its long side is > 2160 px |
| Video | mp4, mov, m4v, webm, mkv | any of: it has an audio stream; video codec is not h264; name does not match `v<number>.mp4`; long side > 1920 px; average bitrate > 2.5 Mb/s; no `<name>.thumb.webp` next to it |

Use `ffprobe -v error -show_entries stream=codec_type,codec_name,width,height:format=duration,bit_rate -of json <file>`
for videos and Pillow for images. Print the classification table before changing anything.
If nothing needs work, skip to step 4.

## 2. Images → WebP (same basename, `.webp`)
For each image that needs processing:
1. Move the original to `images/video-maker-originals/` (rule 0).
2. Open with Pillow, `ImageOps.exif_transpose`, convert to RGB (flatten any alpha on black).
3. If the long side is > 2160 px, downscale with LANCZOS so the long side is 2160 (keep aspect).
4. Encode WebP with `method=6`, no metadata:
   - Lossless/high-bit sources (png, tif, bmp, avif, heic, or an oversized webp): `quality=92`.
   - JPEG sources: already lossy, so re-encoding high only grows the file. Try `quality` from 90
     down to 75 and keep the FIRST (highest) quality whose output is smaller than the original
     JPEG; if none is smaller, use 75.
5. Write `images/video-maker/<basename>.webp`. If that name is already taken by a different
   (already processed) file, use the next free name `<basename>-2.webp`, etc.

## 3. Videos → `v<N>.mp4` + full-size poster
For each video that needs processing:
1. Pick the output name: if it already matches `v<number>.mp4` keep that number; otherwise use the
   next free `v<N>.mp4` (N = 1 + the highest existing number across `images/video-maker/` and
   `images/video-maker-originals/`).
2. Move the original to `images/video-maker-originals/` (rule 0).
3. Encode from the original:
   ```
   ffmpeg -v error -y -i "<original>" -an \
     -vf "scale='if(gt(iw,ih),min(1920,iw),-2)':'if(gt(iw,ih),-2,min(1920,ih))',fps='min(30,source_fps)'" \
     -c:v libx264 -preset slow -crf 28 -pix_fmt yuv420p -profile:v high -movflags +faststart \
     "images/video-maker/v<N>.mp4"
   ```
   (`-an` drops audio — the recitation is the only sound in exported clips. If the `fps` filter
   expression is rejected, compute the source fps with ffprobe and pass `fps=<min(30,src)>`.)
   If the result is still above 2.5 Mb/s average, re-encode once with `-crf 30`.
4. Poster/thumbnail — a FULL-SIZE still from 0.5 s in (the page draws it until the video has a
   frame, so it must not be a small thumbnail):
   ```
   ffmpeg -v error -y -ss 0.5 -i "images/video-maker/v<N>.mp4" -frames:v 1 -c:v libwebp -quality 85 "images/video-maker/v<N>.thumb.webp"
   ```
5. If the video is longer than 30 s, keep it but list it as a warning in the report (long
   backgrounds only cost bandwidth; clips loop anyway).

## 4. Regenerate the manifest
Run `npm run bgs:video`. It must print no "has no thumbnail" warnings.

## 5. Verify
- `images/video-maker/manifest.json` lists every processed image/video and no `.thumb.webp`,
  `.md` or original-format files.
- Every `v*.mp4` has a matching `v*.thumb.webp`, and `ffprobe` shows no audio stream in it.
- Every original that was converted now exists in `images/video-maker-originals/`.
- `npm run verify` passes.

## 6. Report
Print a table: original file → output file, size before → after (KB), dimensions, WebP quality
or video CRF used, plus any warnings (long videos, files Pillow/ffmpeg could not read — leave
those untouched and list them).
